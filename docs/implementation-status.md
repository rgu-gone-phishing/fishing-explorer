# Implementation status — 24 October 2026

The parity goal remains active. The application now retrieves real AIS apparent fishing activity, AIS vessel presence and SAR vessel detections as well as clearly labelled synthetic fixtures. This is an incremental implementation, not a completed parity release.

## Verified saved-data reuse before retrieval

Compatibility uses source/observing product, requested dataset version, units, exact geometry, named-boundary identity/version/simplification, spatial grid, saved time grain, grouping and all supported filters. ## Current limits and next work

- Named-region application supports detailed geometry within the documented limits; antimeridian/polar boundaries and provider simplification semantics remain unresolved. The filtered infrastructure overlay and individual saved-extract GeoTIFF export are implemented. The experimental bulk workflow is implemented, with live provider file validation still pending. Historical raster packaging remains open. Animation is deferred by the specification; synchronized multi-source live previews remain unimplemented.
- Individual live requests are bounded to 366 days and 32 MiB response data by this application; historical plans support up to 240 chunks across roughly 20 years, with 1–12 calendar months per live chunk; these are conservative implementation limits, not asserted provider limits. Artifact envelopes are still in-memory JSON; large extraction requires streaming storage.
- Last-report recovery is deliberately conservative: responses lacking correlation metadata require independent user review. Checking an unavailable/failed last report does not establish ownership or prove the original job never ran. Bounded opt-in recovery polling and provider cooldown handling are implemented. Report resubmission remains a deliberate manual action. Historical batches stop on an unresolved child and require explicit recovery/resume. A queued job can be paused/resubmitted; an active remote computation cannot be paused by this client.
- Individual extracts retain JSON bundles and can export/import documented ZIPs; new historical ZIPs add root handoff documentation alongside original chunk bundles and CSV. ZIP generation uses the store method, with a current 2 GiB data budget and no ZIP64/compression. Import supports Fishing Explorer's own schemas, including bulk archives, rather than arbitrary GFW/VMS/static files. Checksums detect inconsistent bytes; they are not a signature establishing publisher authenticity.
- VMS discovery/evidence handling is implemented; country/product-specific export eligibility, an authorized sample and a verified analytical import adapter remain open. Other documented GFW products are not silently represented as AIS or synthetic data.
- Versioned local preview packaging is implemented and Linux extraction/startup/restart is verified. Windows/Intune deployment, broader accessibility, resource limits, data/use-rights review and the full P0/P1 acceptance matrix remain open.

The initial plain-JavaScript/Node-built-in architecture remains deliberately dependency-light. Leaflet, Natural Earth context geometry and robust-predicates are bundled with notices and provenance in THIRD_PARTY_NOTICES.md. No CDN or remote tile connection is needed to reopen a saved map. Basemap outlines are generalized context, not authoritative jurisdictional boundaries. Saved maps retain coordinate symbols. The separate GeoTIFF writer uses documented cell-centre semantics, checked against the bounded v5 AIS provider sample described above; this does not establish fractional boundary weighting. Analysis geometry supports 250,000 vertices, 2,000 non-overlapping/non-touching polygon parts and 4,000 rings, within the documented coordinate and work limits. No upstream platform code was copied. Source adapters remain separate from artifact integrity and display code.
